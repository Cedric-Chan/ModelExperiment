## 背景与目标

随着评分卡样本持续增长（B 卡训练样本可达 900 万以上），单机训练面临内存瓶颈与迭代效率低的问题。Ray 分布式改造目标如下：

- 使用 Ray Dataset + Modin 并行读取、预处理并分发训练数据。
- 提供可复用的特征处理（WOE、特征选择、报告）、模型调参与训练、推理、校准、mega model 管线。
- 有效管理 S3 存储路径与 RayHub 集群生命周期，确保产出物（模型、报告、日志）可追溯。

## 系统组件概览

整体流程由 Feature 与 Model 两大域组成，全部入口集中在 `util/ray_helper` 内，通过 `RayUtil` 调用：

1. **Feature 域**：`woe_fit` → `woe_transform` → `woe_merge` → `feature_selection` → `feature_report`。
2. **Model 域**：`model_tune` → `model_train` → `model_predict` → `model_bm`。
3. **Score 域**：`calibrate_fit`、`multi_stage_calibrate_fit` 等用于子模型与 mega score 校准。
4. **工具**：`upload_parquet`、`ray_woe_encoder_combine` 等辅助文件管理。

## 环境准备

- Python 3.9 及以上。
- 执行 `pip install -r requirements.txt` 安装依赖（见文末依赖章节）。
- 拥有 Shopee Data Infra S3 访问凭证，可访问 `BaseConfig.fp_s3_endpoint` 指定的对象存储。
- 可访问 RayHub，并具备创建/启动集群的权限。

### Ray 集群规范

- 默认集群名为 `risk-model`，规格由 `cluster_spec.yml` 定义，可按资源需求调整。
- `RayUtil` 在初始化时会自动检查并创建集群，必要时可以传入自定义 `cluster_spec.yml`。
- 将 `RayUtil(enable_log_tail=True)` 打开可实时拉取日志，默认为状态轮询模式。

### 集群区域配置（SG/US）

项目支持新加坡（SG）和美国（US）两个区域的集群配置，通过修改 `BaseConfig.cluster_idc` 进行切换：

- **SG 集群**（默认）：`cluster_idc = 'SG'`
  - S3 端点：`https://s3g.data-infra.shopee.io`
  - RayHub 地址：`https://rayhub.data-infra.shopee.io`
  - 默认路径：`s3://sg-risk-model-prod/risk/id/spl_acard`
- **US 集群**：`cluster_idc = 'US'`
  - S3 端点：`https://us.s3g.data-infra.shopee.io`
  - RayHub 地址：`https://rayhub-us.data-infra.shopee.io`
  - 默认路径：`s3://useast-risk-model-prod/risk/br/spl_acard`

**配置方法：**

在 `config/base_config.py` 中修改：

```python
class BaseConfig:
    def __init__(self):
        self.cluster_idc = 'US'  # 改为 'US' 切换到美国集群，'SG' 为新加坡集群（默认）
        # 系统会自动根据 cluster_idc 设置对应的 S3 端点、RayHub 地址和默认路径
```

修改后，所有任务（WOE、特征选择、模型训练等）将自动使用对应区域的集群和存储。

### config 包重点

- `BaseConfig`：集中管理 `fp_base`（根路径）、S3 endpoint、Ray runtime env、特征元信息与缺失值策略。
- `WoeConfig`：继承 `BaseConfig`，新增 encoder/transform/merge 路径、全局/特征级分箱参数、`get_merge_info_dict`。
- `TuneConfig` / `TrainConfig` / `PredictConfig`：分别维护调参、训练、预测所需输入输出路径、超参与采样列名。
- `FsConfig`：特征选择输入输出路径、方法（`by_iv/by_corr/by_gini/by_psi`）与阈值配置。
- `CalibrateConfig` / `MultiStageCalibrateConfig`：Calibrator v2、multi-stage 的分箱、阶数、特征列、结果路径。
- `BMConfig`：mega model（Logit）训练所需子模型列表与特征约束。
- `ValidConfig`：各任务入口的必填项校验与默认值注入。已废弃

### util 包重点

- `ray_helper/ray_util.py`：Python API，封装 RayHub Job 提交、日志轮询与各任务入口。
- `ray_helper/ray_*.py`：真正运行在集群上的脚本，参数均支持 CLI 覆盖 `config` 默认值。
- `woe_helper/woe_v2_4_ray.py`：WOE v2.4 核心实现，支持 per-feature overrides 与 Ray Dataset。
- `fs_helper/fs_helper_remote.py`：分布式特征选择算子。
- `report_helper/feature_report_v2_4.py`：ActorPool 生成性能、单调性、稳定性报告。
- `model_helper/model_helper.py`：KS/AUC 指标、预测函数封装，供调参与训练脚本复用。
- `calibrate_helper/calibrate_helper_v2*.py`：Calibrator v2 & multi-stage 的拟合/预测逻辑。

  | 参数                  | 默认值                                                  | 说明                                            |

### Step 1：特征工程

#### 1.1 WOE Fit v2.4

入口：`ray_util.woe_fit()` → `util/ray_helper/ray_woe_fit_v2_4.py`。


| 参数                            | 类型    | 默认值/来源                                                                            | 说明                                                                                           |
| ----------------------------- | ----- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `feature_name`                | str   | 必填                                                                                | 特征域名称，对应 `BaseConfig.feature_info` 键值                                                        |
| `data_path`                   | str   | `fp_features/{feature_name}`                                                      | 覆盖原始特征数据的 S3 路径                                                                              |
| `encoder_save_path`           | str   | `fp_model_woe_encoder/{feature_name}_{method}_{n_bins}bin.pkl`                    | 覆盖编码器保存路径                                                                                    |
| `model_level`                 | str   | `sub`                                                                             | `sub` 子模型；传 `mega` 时读取 mega merge 数据                                                         |
| `label`                       | str   | `BaseConfig.label`（默认 `6term_dpd30`）                                              | 标签列名                                                                                         |
| `sample_use_col`              | str   | `BaseConfig.sample_use_col`（默认 `sample_tag`）                                      | 训练/测试划分列名                                                                                    |
| `n_bins`                      | int   | 5                                                                                 | 全局分箱数，可被 `dict_nbins` 覆盖                                                                     |
| `method`                      | str   | `best_ks`                                                                         | 分箱策略，支持 `best_ks` / `quantile`                                                               |
| `transform_method`            | str   | `woe`                                                                             | 输出编码方式，支持 `woe` / `bin`                                                                      |
| `min_bin_rate`                | float | 0.02                                                                              | 单桶最小占比                                                                                       |
| `min_bin_size`                | int   | 50                                                                                | 单桶最小样本数                                                                                      |
| `min_missing_bad_cnt`         | int   | 30                                                                                | 缺失值桶最小坏样本数                                                                                   |
| `categorical_features`        | list  | `BaseConfig.feature_info[feature].categorical_features`                           | 分类特征列表                                                                                       |
| `missing_values`              | list  | `BaseConfig.feature_info[feature].missing_values`                                 | 需单独分桶的缺失取值                                                                                   |
| `missing_logic`               | dict  | None                                                                              | 自定义 NA 风险映射，如 `{"feature": "high_risk"}`                                                     |
| `ls_high_risk_na_features`    | list  | `BaseConfig.missing_values_info.highest_risk`                                     | 高风险缺失列名单                                                                                     |
| `ls_neutral_risk_na_features` | list  | `BaseConfig.missing_values_info.neutral`                                          | 中性缺失列名单                                                                                      |
| `dict_nbins`                  | dict  | None                                                                              | 特征级分箱数，如 `{"feat": 6}`                                                                       |
| `dict_missing_values`         | dict  | None                                                                              | 特征级缺失值列表                                                                                     |
| `dict_min_bin_rate`           | dict  | None                                                                              | 特征级最小占比                                                                                      |
| `dict_min_bin_size`           | dict  | None                                                                              | 特征级最小样本数                                                                                     |
| `dict_min_missing_bad_cnt`    | dict  | None                                                                              | 特征级缺失值坏样本阈值                                                                                  |
| `exclude`                     | list  | `BaseConfig.exclude + feature_info.removed_features + user_exclude（如果有）+ [label]` | 训练时剔除的列；最终 exclude = base_config.exclude + removed_features + 用户传入的 exclude（追加，不覆盖）；标签列会自动加入 |


> 提示：除表中字段外，所有 `BaseConfig` / `WoeConfig` 中的路径、凭证（如 `fp_s3_endpoint`、`fp_model_woe_encoder`、`rayhub_addr` 等）均可通过同名 CLI 参数覆盖，`RayUtil.woe_fit` 会将关键字参数拼接为 `--{param}` 传递给脚本。

> **v1.4 修复**：修复了 `categorical_features` 可能不会正确分到 `cat_missing` 桶的BUG。现在分类特征的缺失值会正确识别并分配到对应的缺失值桶中。

#### 1.2 WOE Transform v2.4

入口：`ray_util.woe_transform()` → `util/ray_helper/ray_woe_transform_v2_4.py`。


| 参数                  | 类型  | 默认值/来源                                                                   | 说明                                                                          |
| ------------------- | --- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `feature_name`      | str | 必填                                                                       | 与 Fit 阶段保持一致                                                                |
| `sample_type`       | str | `training_features`                                                      | 支持 `training_features` / `test_features` / `oot_features` / `ooot_features` |
| `model_level`       | str | `sub`                                                                    | `sub` 子模型或 `mega` mega 模型                                                   |
| `ooot_date`         | str | None                                                                     | 仅当 `sample_type` 为 `ooot_features` 时必填，用于定位分区                               |
| `data_path`         | str | 根据 `sample_type` 与 `model_level` 自动拼接                                    | 覆盖输入数据路径                                                                    |
| `data_save_path`    | str | `fp_model_woe_transformed_data/{sample_type}_{feature_name}_{n_bins}bin` | 输出数据路径，可自定义                                                                 |
| `encoder_load_path` | str | 自动匹配 `fp_model_woe_encoder/{feature_name}_{method}_{n_bins}bin.pkl` 等文件  | 可手工指定 S3 路径                                                                 |

> 说明：Transform CLI 同样支持传入 `dict_*`、`missing_*` 等参数，但正常情况下无需调整；脚本主要依赖保存好的 encoder。当覆盖 `n_bins` 或 `method` 时请确保对应编码器已经存在。

> **v1.4 修复**：修复了当标记 `categorical_features` 但原始数据为 float 类型时导致 transform 失效的BUG。现在系统会自动进行类型转换，确保分类特征能够正确编码。

执行示例：

```python
ray_util.woe_transform(

    data_save_path="s3://sg-risk-model-prod/risk/id/spl_acard/woe/data/features/training_features_acard_ft_user_v1_5bin",
    encoder_load_path="s3://sg-risk-model-prod/risk/id/spl_acard/woe/encoder/acard_ft_user_v1_best_ks_5bin.pkl",
    transform_method="woe"
)
```

#### 1.3 WOE Merge

#### 1.3.1 WOE Merge v2（Ray 原生 Join API）

入口：`ray_util.woe_merge_v2()` → `util/ray_helper/ray_woe_merge_v2.py`。

`woe_merge_v2` 使用 Ray 原生 `join` API 进行数据合并，相比 `woe_merge`（基于 Modin Pandas）具有更好的内存效率和稳定性。


| 参数               | 类型   | 默认值/来源                                               | 说明                                                               |
| ---------------- | ---- | ---------------------------------------------------- | ---------------------------------------------------------------- |

### Step 2：特征选择

**Stability Selection 原理说明：**

`by_stability` 方法基于 Stability Selection 算法，通过多次重采样和 L1 正则化逻辑回归来选择稳定特征：

1. **重采样**：对训练数据进行 `n_resampling` 次随机子采样（每次采样 `sample_fraction` 比例的样本）。
2. **多 lambda 训练**：对每个重采样数据集，使用 `lambda_grid` 中的每个 lambda 值训练 L1 正则化逻辑回归模型。
3. **统计选择频率**：统计每个特征在不同 lambda 值下被选中（系数非零）的频率，得到稳定性分数（stability scores）。
4. **特征筛选**：选择最大稳定性分数 >= `stability_threshold` 的特征作为最终结果。

该方法能够识别在不同数据子集和正则化强度下都稳定被选中的特征，提高特征选择的鲁棒性。

**分布式 L1 LR 实现原理：**

`by_stability` 方法使用分布式坐标下降法（Coordinate Descent）求解 L1 正则化逻辑回归，核心思想是将数据分片到多个 worker 节点并行计算梯度和 Hessian，然后在 driver 节点更新参数。

**训练流程（单个 lambda，单次重采样）：**

```
┌─────────────────────────────────────────────────────────────┐
│                    Driver 节点（协调者）                      │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  1. 初始化 w = 0（包含截距）                          │  │
│  │  2. 将重采样数据分片到 N 个 worker 节点               │  │
│  │  3. 外层循环：坐标下降迭代（最多 max_iter 次）        │  │
│  └──────────────────────────────────────────────────────┘  │
│                         │                                    │
│                         │ 广播当前 w                        │
│                         ▼                                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  4. 聚合所有分片的梯度 grad 和 Hessian hess          │  │
│  │     grad_total = Σ(grad_i) / n_total                 │  │
│  │     hess_total = Σ(hess_i)                           │  │
│  └──────────────────────────────────────────────────────┘  │
│                         │                                    │
│                         │ 更新每个坐标                       │
│                         ▼                                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  5. 遍历所有坐标 j（特征 + 截距）：                   │  │
│  │     - 截距 (j=0): w[j] = w[j] - grad[j]/hess[j]     │  │
│  │     - 特征 (j>0): 使用 soft-thresholding            │  │
│  │       w_newton = w[j] - grad[j]/hess[j]             │  │
│  │       threshold = lambda / hess[j]                    │  │
│  │       w[j] = sign(w_newton) * max(0, |w_newton|-threshold)│
│  │  6. 检查收敛：||w_new - w_old|| < tol                │  │
│  │  7. 更新 w = w_new                                    │  │
│  └──────────────────────────────────────────────────────┘  │
│                         │                                    │
│                         │ 未收敛则继续迭代                    │
│                         └─────────────────┐                  │
│                                           │                  │
└───────────────────────────────────────────┘                  │
                                                                │
┌───────────────────────────────────────────────────────────────┐
│                    Worker 节点（并行计算）                      │
│                                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│  │Worker 1  │  │Worker 2  │  │Worker 3  │  │Worker N │      │
│  │          │  │          │  │          │  │          │      │
│  │X_part_1  │  │X_part_2  │  │X_part_3  │  │X_part_N │      │
│  │y_part_1  │  │y_part_2  │  │y_part_3  │  │y_part_N │      │
│  │          │  │          │  │          │  │          │      │
│  │计算:     │  │计算:     │  │计算:     │  │计算:     │      │
│  │logits=Xw │  │logits=Xw │  │logits=Xw │  │logits=Xw │      │
│  │probs=σ(.)│  │probs=σ(.)│  │probs=σ(.)│  │probs=σ(.)│      │
│  │residual  │  │residual  │  │residual  │  │residual  │      │
│  │grad=X^T* │  │grad=X^T* │  │grad=X^T* │  │grad=X^T* │      │
│  │  residual│  │  residual│  │  residual│  │  residual│      │
│  │hess=Σ(X² │  │hess=Σ(X² │  │hess=Σ(X² │  │hess=Σ(X² │      │
│  │  *weights)│  │  *weights)│  │  *weights)│  │  *weights)│      │
│  │          │  │          │  │          │  │          │      │
│  │返回:     │  │返回:     │  │返回:     │  │返回:     │      │
│  │grad_1    │  │grad_2    │  │grad_3    │  │grad_N    │      │
│  │hess_1    │  │hess_2    │  │hess_3    │  │hess_N    │      │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘      │
│       │              │              │              │          │
│       └──────────────┴──────────────┴──────────────┘          │
│                         │                                      │
│                         │ 返回 grad_i, hess_i                 │
│                         ▼                                      │
└───────────────────────────────────────────────────────────────┘
```

**关键优化：**

1. **批量计算梯度/Hessian**：每个 worker 节点一次性计算所有坐标的梯度和 Hessian，减少远程调用次数。
2. **坐标下降更新**：Driver 节点聚合梯度/Hessian 后，逐个坐标更新参数，对特征使用 soft-thresholding 实现 L1 正则化。
3. **内存优化**：数据分片存储在 Ray Object Store，避免在 driver 节点加载完整数据集，防止 OOM。
4. **并行重采样**：支持并行训练多个 lambda 值（`parallel_lambdas=True`），或串行训练以支持 warm-start。
5. **数值稳定性**：限制 logits 范围防止溢出，使用合理的 Hessian 下界避免除零错误。

输出：

- `selection_report_{model_name}.csv`：汇总报告，标记每个特征被哪些方法选中。
- `feature_list_{model_name}_{method}.csv`：各方法的详细筛选结果。

### Step 3：模型调参（Ray Tune）

入口：`ray_util.model_tune()` → `util/ray_helper/ray_tune.py`。

流程要点：

1. **配置初始化**：`TuneConfig` 字段支持 CLI 覆盖，`ValidConfig` 校验必填项。
2. **数据读取**：Modin 过滤 `train` 样本，合并 `exclude`, `tune_exclude_cols`, 特征选择剔除列，并拆分训练/验证。
3. **搜索策略**：默认 `BayesOptSearch` + `ConcurrencyLimiter`，并支持 `TrialPlateauStopper` 早停。
4. **Trainer**：基于 `LightGBMTrainer` 或 `XGBoostTrainer`（取决于 `init_hypers`），`ScalingConfig` 控制 worker 数量。

### Step 6：Mega Model（BM）

项目提供两个版本的基准模型训练工具：

#### 6.1 Ray BM v2（分布式 LR）

入口：`ray_util.model_bm_v2()` → `util/ray_helper/ray_bm_v2.py`。

`ray_bm_v2` 使用分布式逻辑回归（RayLogit）训练基准模型，并提供多种特征选择与系数筛选策略。

**分布式 LR 实现原理：**

`ray_bm_v2` 基于 IRLS（迭代重加权最小二乘）算法实现分布式逻辑回归，核心思想是将数据分片到多个 worker 节点并行计算，然后在 driver 节点聚合结果。

**训练流程：**

```
┌─────────────────────────────────────────────────────────────┐
│                    Driver 节点（协调者）                      │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  1. 初始化 beta = 0                                  │  │
│  │  2. 将数据分片到 N 个 worker 节点                    │  │
│  │  3. 广播当前 beta 到所有 worker                       │  │
│  └──────────────────────────────────────────────────────┘  │
│                         │                                    │
│                         │ 广播 beta                          │
│                         ▼                                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  4. 聚合所有分片的 XtWX 和 XtWz                      │  │
│  │     XtWX_total = Σ(XtWX_i)                           │  │
│  │     XtWz_total = Σ(XtWz_i)                           │  │
│  └──────────────────────────────────────────────────────┘  │
│                         │                                    │
│                         │ 求解线性方程组                     │
│                         ▼                                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  5. 求解 (XtWX_reg) * beta_new = XtWz                │  │
│  │     其中 XtWX_reg = XtWX_total + L2 * I              │  │
│  │  6. 检查收敛：||beta_new - beta|| < tol               │  │
│  │  7. 更新 beta = beta_new                              │  │
│  └──────────────────────────────────────────────────────┘  │
│                         │                                    │
│                         │ 未收敛则继续迭代                    │
│                         └─────────────────┐                  │
│                                           │                  │
└───────────────────────────────────────────┘                  │
                                                                │
┌───────────────────────────────────────────────────────────────┐
│                    Worker 节点（并行计算）                      │
│                                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│  │Worker 1  │  │Worker 2  │  │Worker 3  │  │Worker N │      │
│  │          │  │          │  │          │  │          │      │
│  │X_part_1  │  │X_part_2  │  │X_part_3  │  │X_part_N │      │
│  │y_part_1  │  │y_part_2  │  │y_part_3  │  │y_part_N │      │
│  │          │  │          │  │          │  │          │      │
│  │计算:     │  │计算:     │  │计算:     │  │计算:     │      │
│  │eta = Xβ  │  │eta = Xβ  │  │eta = Xβ  │  │eta = Xβ  │      │
│  │μ = σ(η)  │  │μ = σ(η)  │  │μ = σ(η)  │  │μ = σ(η)  │      │
│  │W = μ(1-μ)│  │W = μ(1-μ)│  │W = μ(1-μ)│  │W = μ(1-μ)│      │
│  │z = η+... │  │z = η+... │  │z = η+... │  │z = η+... │      │
│  │XtWX_1    │  │XtWX_2    │  │XtWX_3    │  │XtWX_N    │      │
│  │XtWz_1    │  │XtWz_2    │  │XtWz_3    │  │XtWz_N    │      │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘      │
│       │              │              │              │          │
│       └──────────────┴──────────────┴──────────────┘          │
│                         │                                      │
│                         │ 返回 XtWX_i, XtWz_i                  │
│                         ▼                                      │
└───────────────────────────────────────────────────────────────┘
```

**关键优化：**

1. **数据分片**：训练数据按行分片到多个 worker 节点，每个节点独立计算局部统计量。
2. **并行计算**：每个 worker 节点并行计算 `XtWX`（特征协方差矩阵）和 `XtWz`（加权特征-标签乘积），无需传输原始数据。
3. **聚合求解**：Driver 节点聚合所有分片的结果，求解线性方程组得到新的参数估计。
4. **容错机制**：支持 ObjectRef 失效自动恢复，可重新创建分片继续训练。
5. **数值稳定性**：使用 `scipy.special.expit` 优化 sigmoid 计算，限制 eta 范围防止溢出，支持 jitter 机制处理奇异矩阵。

该方法能够处理大规模数据（千万级样本），通过分布式计算显著提升训练效率。

## 配置与调优建议

- **路径管理**：推荐为每次实验复制一份 `BaseConfig.fp_base` 根路径，避免产出互相覆盖。
- **凭证切换**：`BaseConfig` 中预留了两个账户可切换，按环境（生产/开发）选择。
- **特征元信息**：`BaseConfig.feature_info` 提供分类特征、缺失值、剔除特征（`removed_features`），WOE Fit 会自动合并。`exclude` 的最终值 = `BaseConfig.exclude` + `feature_info[feature_name].removed_features` + 用户传入的 `exclude`（追加，不覆盖），例如分类特征的 NA 调整策略。
- **Merge 信息**：`WoeConfig.get_merge_info_dict` 在 `model_level='sub'/'mega'` 时自动返回合并映射，可通过 `data_path_dict` 手动覆盖。
- **调参规模**：大样本（>1000 万）建议 `num_workers` 调整到 35-40，确保 `cluster_spec.yml` 资源充足。
- **KS 惩罚**：`coeffcient_overfit_punishment` 与 `train_val_ks_diff_threshold` 联动，鼓励选择泛化性更好的参数组合。
- **特征报告**：建议在 WOE Transform 后立即生成报告，校验分箱单调性、稳定性，避免下游调参失败。
- **编码器后处理**：如需微调单个特征，优先使用 `woe_update` / `woe_set_woe` 等工具，避免重复跑全链路。
- **Calibrate 策略**：v2.1 推荐应用多阶段校准处理 mega score，默认断点 `[900, 600]` 可按业务需求调整。

## 常见问题

1. **分箱组合过多**：`n_bins` 过大、`min_bin_rate` 过小时组合数暴涨，建议逐步上调 `min_bin_rate` 或增加 `dict_nbins` 精细化控制。
2. **Encoder 未找到**：确保 `encoder_load_path` 指向包含 `feature_name`、`method`、`n_bins` 的文件，或检查 `fp_model_woe_encoder` 路径是否一致。
3. **特征选择列缺失**：如未开启 `use_feature_selection`，请在 `TuneConfig` / `TrainConfig` 中传入 `use_feature_selection=[]` 或修订 CSV 列名。
4. **Ray 作业 Pending**：通常为集群资源不足或启动中，检查 RayHub 控制台或提高 `cluster_spec.yml` 中的 worker 数量。
5. **Calibrator 输出为空**：确认 `feature_list` 列存在且概率列未出现异常缺失，同时检查 `sample_path` 是否包含 `train/test` 样本。
6. **特征报告特征筛除导致内存问题**：在 `feature_report` 链路中若需根据特征选择结果剔除列，请直接使用 Ray Dataset API（如 `select_columns`、`drop_columns` 等）在分布式数据集上处理，避免使用 `to_pandas()` / `from_pandas()` 将数据收缩成单分片引发内存瓶颈。参阅 [https://docs.ray.io/zh/latest/data/api/dataset.html](https://docs.ray.io/zh/latest/data/api/dataset.html) 获取更多示例。
